# Security audit, 2026-11-19

Self-run. **This is not an independent review**: the same party that wrote the code ran it, with four separate reviewers that each read one surface from the code (not from a summary), and every finding was then reproduced or traced by hand before it was fixed. An independent review by an outside party is still required before a stable release (the maintainers' record "STABLE_GATE.md" (not published)).

Nothing here was tested against a real customer's data or a third party's system. Tests ran against the code in temporary folders, the Firebase emulators, and read-only or disposable checks of the project's own production services.

References used as checklists, not as certifications: OWASP ASVS 5.0, the OWASP Web Security Testing Guide, the OWASP Top 10 for agentic applications, NIST SSDF (SP 800-218). No conformance to any of them is claimed.

## Threat model

| Boundary | Who is not trusted | What is relied on | Where it is enforced |
|---|---|---|---|
| Public website (static, GitHub Pages) | Every visitor; any other website; the static host cannot send security headers | Nothing in the browser decides access | Firestore rules; the companion; a frame guard in the page |
| Firebase (Auth, Firestore) | Any internet user with the public web key and their own account; a tampered client | Firestore rules only. No server code, no Admin SDK in any shipped file | `firestore.rules`, proven in the emulator (`e2e/rules.spec.ts`, `e2e/early-access-emulator.spec.ts`) |
| Phone relay (Firestore documents) | The relay itself; other signed-in accounts; a revoked phone; a hostile page on the phone | Signatures and encryption with keys the relay never holds; trust given on the desktop only | `packages/remote`, `packages/companion/src/remote-*.ts`, the phone's own checks in `apps/dashboard/src/remote-verify.ts` |
| Companion (local HTTP on 127.0.0.1) | Any website the person visits; any other local web page or port; an outside page the person allowed; the agent it starts | Pairing code shown in the terminal; a session value kept in port-isolated storage; a fresh confirmation code for each human action | `packages/companion/src/index.ts` |
| Agent (Claude Code, Codex, others) | The agent itself, steered by hostile Markdown, web pages, MCP results or files | Hooks call the gate before a tool runs; the gate decides from the goal, the policy and approvals a person gave | `packages/core/src/classify.ts`, `decide.ts`; `packages/adapters` |
| Disk | A same-user process (see limits) | Protected paths, the denied state folder, a hash-chained record | `packages/core` |

Limits that are disclosed and unchanged (see `SECURITY.md`): a program running as the same user can read or rewrite this product's files; in the standard profile a script's own network activity is not seen; Codex runs an action if its hook program is missing; "verified" is only as strong as the check a person wrote.

## Findings

Severity: P0 critical, P1 high, P2 medium, P3 low. "Fixed" means fixed in source with a regression test that fails without the fix. A fix in the companion, the CLI or the policy engine reaches installed computers only with a new binary; a fix in the rules needs a rules deploy; a fix in the site needs a Pages deploy. The release state of each is in the maintainers' record "MASTER_MATRIX.md" (not published).

No P0 finding.

## Attack classes checked and found defended

Each row was traced in code and has a test. The full tables are the reviewers' reports summarised in the maintainers' record "MASTER_MATRIX.md" (not published).

- **Cross-site and local-network:** Host, Origin and Sec-Fetch-Site checks; exact-origin CORS with no wildcard and no credentials; DNS rebinding; an allowed outside page cannot act without a code typed from the terminal, bound to the exact request and used once (`companion.test.ts`, `workspace.test.ts`).
- **Self-approval:** no MCP tool approves, changes policy or creates a task (`mcp.test.ts`, the tool list is pinned); the CLI's human commands need a real terminal (`tty.test.ts`); every one of the companion's 24 human operations refuses no code, a wrong code, a used code and another session's code, and leaves the record unchanged (`human-ops-table.test.ts`).
- **Approval scope:** bound to the exact effect and target, the goal version, the policy version and the agent; single use; expiring; not carried by a handoff (`hardening.test.ts`, `handoff.test.ts`).
- **False "verified":** status comes only from the engine's own run of the check; a claim never satisfies a criterion; an edited test, a lowered threshold or a skipped test withholds the status (`weak-criteria.test.ts`, `drift.test.ts`).
- **Record integrity:** a single edited, deleted, reordered or truncated event is detected; a damaged record fails closed (`hardening.test.ts`, `release-blockers.test.ts`).
- **Path traversal:** `..`, absolute paths, drive letters, UNC paths, junctions and the `.git` folder are refused in every file route (`workspace.test.ts`, `diff.test.ts`).
- **Uploads:** type decided from the bytes; SVG, programs and oversized files refused; never served back; the name is not put in the prompt (`attachments.test.ts`).
- **Hostile content:** Markdown and file content are shown as text and run nothing (`e2e/workspace.spec.ts`).
- **Accounts:** no account reads, lists or writes another's documents in any of 18 rule blocks; no account can make itself administrator, approve its own application or redeem another's invitation; revocation is read on every request (`e2e/rules.spec.ts`, `e2e/early-access-emulator.spec.ts`, `e2e/accounts.spec.ts`).
- **Phone link:** replay, old counters, concurrent copies, expiry and restart; an untrusted or revoked device gets no answer; a phone cannot approve a push or a protected write, change policy or register a project (`remote-host.test.ts`, `remote-actions.test.ts`, `protocol.test.ts`).

## What was inspected the way an outsider would

- **Published binaries (1.0.0-rc.7):** all eight files match `SHA256SUMS`; the installers the live site serves are byte-identical to the release's; all nine release files carry a valid GitHub build attestation naming the public repository, the tag `v1.0.0-rc.7` and commit `628d0c6`. The Windows package and the VS Code extension contain no secret-like string, no private path, no personal email address and no privileged SDK. The bundled `node.exe` is the official one, signed by the OpenJS Foundation. AgentOnTrack's own files are JavaScript and are **not code-signed**; the install scripts are not signed either (see `docs/release/BINARY_README.md`).
- **Public source history:** 72 commits scanned for keys, tokens and private keys: one match, a made-up key in a test fixture. No private path. One personal email address as commit author (SEC-30).
- **Dependencies:** 2 advisories, both moderate, both in a build-time packaging tool for the VS Code extension that is not shipped. Licences: MIT, Apache-2.0, ISC, BSD-3-Clause; MPL-2.0 only in test and build tools.
- **Live site:** HTTPS enforced by redirect; the dashboard page carries a strict content policy (`script-src 'self'`, no inline script); the marketing pages have none (static host). No security response headers are possible on this host.
- **Production Firestore, as an anonymous caller:** every collection read, list and collection-group query answered 403.

Reverse engineering cannot be prevented: everything shipped is readable JavaScript by design, and nothing in it is a secret or a place where access is decided.
