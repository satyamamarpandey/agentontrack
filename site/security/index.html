Security

What is protected, against whom, and where it stops. Reports are welcome.

Prevented

  • Statically recognised consequential commands, and file writes through file tools and most shell commands, until you approve them.
  • All opaque programs, if you choose the strict profile.
  • Self-approval through MCP, and through a shell without a terminal or, if enrolled, the passphrase.

Detected afterwards

  • File changes by scripts inside the project.
  • Changes to a short list of sensitive files outside it.
  • Edits to the log that do not also rewrite the witness.

Not covered

  • Network and process effects of a script in standard mode.
  • A same-user program that rewrites both the log and the witness. An external anchor is the only way to catch that.
  • A test hollowed out while keeping its counts.
  • Tools a runtime does not route through hooks.

Local dashboard

It listens on loopback only. Knowing the port grants nothing: it checks Host and Origin, needs a pairing code that works once, a strict HttpOnly cookie and a CSRF token, and each human action needs a fresh confirmation code.

This website

The site is static, with no account and no server. Its dashboard connects only to a companion you started with --allow-public-site and paired with a code. That setting trusts the origins pandeysatyam.com and satyamamarpandey.github.io, which every Pages site on this GitHub account shares. The pairing code and per-action confirmation still apply.
